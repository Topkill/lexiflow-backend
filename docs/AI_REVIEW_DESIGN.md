# AI 评阅格式设计讨论

## 结论

当前更适合采用“混合方案”：

- AI 负责产出结构化内容。
- 后端负责把结构化内容整理成稳定的章节骨架。
- 前端负责 Markdown 渲染和视觉排版。

## 取舍

### 直接让 AI 输出最终 Markdown

优点：

- 改动少。
- AI 的语气和强调感更自然。

缺点：

- 格式稳定性差，标题层级、列表样式容易漂。
- 后续做统计、二次展示、移动端适配时不方便。
- 前端仍然要做视觉渲染，不能真正省掉排版成本。

### 继续用结构化 JSON + 后端组装

优点：

- 结构稳定，便于缓存、回放和扩展。
- 章节层级统一，前端渲染更容易控制。
- 后续如需改展示风格，不必重做 AI 提示词。

缺点：

- 后端要维护一层 formatter。
- 前端仍需做一些 Markdown 样式调整。

## 当前采用的做法

- AI 返回 JSON。
- 后端把 JSON 组装成 Markdown 展示文本。
- 前端只做 Markdown 渲染和样式控制。
- 在 prompt 中只额外约束 AI：
  - 关键结论可以用 `**加粗**`
  - 英文词可以用 `` `resume` `` 这类反引号包裹

## 不纳入 prompt 的项

- 不要求 AI 自己输出固定大标题结构。
- 不额外要求 AI 把每条建议压短。
- 如果既是关键结论又是英文词，可以**`auto`**

这两项留给后端结构和前端样式继续控制，避免模型输出漂移。
